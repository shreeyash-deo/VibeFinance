1. Goal and hard rules
Build a multi-agent system that takes one ticker + one user profile and returns a
personalized, cited, confidence-scored recommendation with the full reasoning chain
visible. Scope: 18 Nifty 50 stocks. Product framing: decision support, never buy/sell calls
(show a SEBI-style disclaimer).
Non-negotiable rules:
1. Indicators and signals are computed by deterministic Python (pandas), never by the
LLM. The LLM only explains and synthesizes.
2. Every agent returns the same Pydantic AgentOutput contract.
3. No recommendation is emitted without at least one citation. If none exists, output
'insufficient evidence, wait'.
4. Demo runs from a frozen snapshot by default; Live mode is a toggle. The app must
never crash on a failed feed.
5. Everything runs with docker compose up .
6. Simulated/synthetic data is labeled as such in the UI and README.
2.Tech stack
Python 3.11, FastAPI, SQLAlchemy 2.x (async), Alembic, Pydantic v2
PostgreSQL 16 + pgvector
LangGraph (orchestration), LangSmith (tracing), LangChain (retrievers/loaders only)
LLM: hosted API primary (configurable via env), Ollama fallback (e.g. llama3.1:8b)
Embeddings: BAAI/bge-small-en-v1.5 via sentence-transformers (local, 384 dims)
Sentiment: FinBERT ( ProsusAI/finbert ) locally, LLM fallback
Indicators: pandas , pandas-ta or ta
Data: yfinance , feedparser , httpx , beautifulsoup4 , pypdf
Auth: none for the MVP (no login, no JWT); the active demo persona is sent in the
header X-User-Id

7. Agents (specification)
7.1 Momentum Agent(deterministic)
Inputs: 1y prices. Compute RSI(14), MACD(12,26,9) histogram, SMA20/50/200, 20d and
60d return, distance from 52w high. Scoring: +1 each for RSI in 50-70, MACD hist > 0 and
rising, close > SMA50 > SMA200, 20d return > 0. -1 for the mirror conditions. RSI > 75 adds
an 'overbought' note. Score in [-4,4] maps to signal: >=2 bullish, <=-2 bearish, else neutral.
Confidence = min(0.9, 0.4 + 0.12*abs(score)), minus 0.15 if data is stale. LLM writes the 2-
4 sentence reasoning from the metrics dict. Evidence: price-derived items (e.g. 'RSI 71.2
on 2025-01-10').
7.2 Volume Anomaly Agent(deterministic)
Compute volume z-score vs the 20-day mean/std, ratio to 20d average, and price change
on the spike day. Signal: z >= 2 with price up is 'anomalous' + bullish bias, z >= 2 with price
down is 'anomalous' + bearish bias (record the bias in metrics), else neutral. Confidence
scales with min(z/4, 1) from 0.4 to 0.85. If delivery % is not available, say so in notes (don't
invent it).

7.3 Sentiment Agent
Fetch the last 14 days of headlines. Score each with FinBERT (positive/negative/neutral
probs). Aggregate with recency weighting (half-life 5 days). Signal: weighted score > +0.2
bullish, < -0.2 bearish, else neutral. Confidence from headline count and agreement (low if
fewer than 3 headlines or high variance). Evidence = top 3 most influential headlines with
URL. If FinBERT fails, fall back to LLM scoring with structured JSON output.
7.4 Filings RAG Agent(CRAG)
See Section 8. Output: signal derived from LLM reading of graded chunks (structured
JSON: stance, key_risks[], key_positives[], supporting chunk ids). Every claim must
reference a chunk id; post-validate that cited ids exist in the retrieved set, else drop the
claim. If zero relevant chunks survive grading, return signal='no_data' ,
status='degraded' , note 'No supporting document found'.
7.5 Flow Agent(optional, build last)
FII/DII 5-day and 20-day net flow trend. Market-wide context only; low weight in synthesis.
7.6 Conflict Detector (deterministic)
Take all agent outputs with status != failed and signal != no_data . Map bullish=+1,
bearish=-1, neutral=0, anomalous uses its bias. Conflict if at least one +1 and at least one -1
with each confidence >= 0.5. Output: conflict: bool , pairs: [(agentA, agentB)] ,
disagreement_score (stdev of weighted signals), and explanation text.
7.7 Risk / Personalization Agent(deterministic core + LLM wording)
Inputs: user profile, holdings, behavior history, current prices, ticker sector. Compute:
Current weights, sector exposure, HHI (sum of squared weights), top-holding weight.
Hypothetical position: what is the sector exposure and HHI after adding x% of this
ticker (x = profile-derived cap).
Stock volatility (annualized 60d std) vs tolerance band (conservative <= 22%,
moderate <= 32%, aggressive no cap).
Behavior flags: overtrading_score > 0.6 , recent panic_sell within 30 days on a
falling stock, loss_aversion > 0.7 .

Outputs a RiskVerdict : max_position_pct , blocked_reasons[] ,
behavioral_nudges[] , concentration_before/after , risk_fit: good|stretch|poor .
Rules (examples):
Volatility above tolerance, or negative filing evidence with a conservative profile →
risk_fit=poor , max position 0%.
Sector exposure after trade > sector limit → cap position to the remaining headroom.
Overtrading flag and the recommendation is a buy on a recent drop → add a 48-hour
cooling-off nudge.
Aggressive profile → cap at max_single_stock_pct , may accept moderate volatility.
7.8 Synthesis Agent
Inputs: all AgentOutputs, ConflictReport, RiskVerdict, profile. Step 1 (deterministic):
compute weighted composite. Weights: momentum 0.25, volume 0.15, sentiment 0.20,
filings 0.30, flow 0.10 (renormalize over agents that are ok/degraded with data).
Confidence = weighted mean confidence x (1 - 0.5*disagreement) x (0.85 if any
degraded/stale) and floor/cap into [0.05, 0.95]. Step 2 (deterministic action mapping):
composite and RiskVerdict map to accumulate | hold | avoid | wait | reduce plus
position_size_pct . Conflict → wait with low confidence. Risk poor → avoid or wait .
Behavioral flag → wait (48h). Step 3 (LLM): write a plain-English summary (<= 150 words)
from the structured facts only, with inline citation markers [1] [2] mapped to the
evidence list. Validator: reject and retry once if summary contains numbers not present in
inputs; then fall back to a templated summary. Citation guard: if no evidence with a filing
or news source is attached, force action wait and summary 'Insufficient sourced
evidence'.

10. LangGraph design
State ( TypedDict /Pydantic): session_id, ticker, user_id, flags, prices_df_ref,
features, agent_outputs: dict, conflict, risk, recommendation, errors,
timings .
Nodes: ingest → features → fan-out to momentum , volume , sentiment , filings_rag ,
flow (parallel branches; reducers merge into agent_outputs ) → conflict → risk →
synthesis → evaluate_and_log .
Requirements: per-node latency recorded; per-node timeout (e.g. 25s for LLM nodes); a
failed node never aborts the graph; LangSmith tracing enabled via env; provide a
sequential runner for the parallel-vs-sequential latency comparison metric. The runner
streams step events (SSE) so the UI can show the reasoning timeline live.

11. Graceful degradation (UI-triggerable)
1. Feed down ( simulate_feed_down ): price provider raises → fall back to cache,
stale=True , momentum/volume confidence -0.15, banner 'stale data as of <date>'.
2. Missing filing (use WIPRO or simulate_missing_filing ): filings agent returns
no_data ; excluded from the confidence calculation; UI shows 'No supporting
document found'; the recommendation must still cite news or price evidence or force
wait .
3. Conflicting agents (use TATAMOTORS): conflict detector fires; synthesis emits wait ,
shows both sides and why, low confidence.
4. LLM down: switch to Ollama; if that fails, use templated summaries from structured
facts.
Each path must be covered by an automated test asserting no exception, a valid response
schema, and at least one citation or a forced wait .
12. Metrics and evaluation
Per session, write to session_metrics : latency_<agent>_ms , latency_total_ms ,
latency_sequential_est_ms , concentration_before , concentration_after ,
retrieval_relevance , agents_ok_count , degraded_flag .
Backtest ( eval/backtest.py , CLI + admin endpoint): for each ticker and each trading
day over the last ~18 months of the snapshot (using only data up to that day, no look￾ahead), run the momentum and volume agents' deterministic logic; compare signal to the
30-day forward return. bullish hit = fwd return > 0, bearish hit = < 0. Store hit rate and
mean forward return per agent, plus n_signals. Sentiment and filings are not backtested
(document why; no historical text archive). Optional: confidence calibration (bucket
confidence into 5 bins, plot predicted vs actual hit rate). Report honestly even if hit rates
are near 50%.
